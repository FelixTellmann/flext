PHASE 1

Preflight — no window, no risk

where: local terminal + PlanetScale dashboard + password manager

Everything here is safe to do today and none of it is time-boxed. The goal is that when the PlanetScale window opens, it is spent only on the transfer.

  • Risk

    The export runbook was written on 2026-07-26, two weeks ago. If the 24-hour re-open offer was tied to a deadline, it may have lapsed. Check this first — it decides whether Phase 3 runs at all. If the data is gone: skip Phases 3–4, and in Phase 5 use the schema-generate + reseed path instead. The only loss is the /books vote counts; the auth tables were always empty.

  • brew install planetscale/tap/pscale mysql-client
pscale auth login
  • openssl rand -hex 32   # MAIL_ENCRYPTION_KEY (64 hex chars)
openssl rand -hex 32   # JWT_SECRET (≥ 32 chars required)
    Back up separately

    Mailbox credentials are stored AES-256-GCM encrypted with MAIL_ENCRYPTION_KEY. A database dump without this key restores nothing usable — it must live somewhere that is not the database and not only Coolify.

  • The single account permitted to sign in to /admin. Presumably felixtellmann@gmail.com.

  • Needed for the DNS records in Phase 6. It's on the server overview in the Hetzner console, or in Coolify under the server settings.

PHASE 2

Coolify: create the MySQL service

where: Coolify dashboard

  • Database name flext. Confirm the data directory is on a persistent volume.

  • The app connects over Coolify's private Docker network. Keeping MySQL off the public interface is the security model — and it means DATABASE_CA_PATH can stay unset (TLS matters only if the connection leaves the box).

  • mysql://<user>:<password>@<internal-host>:3306/flext

    The internal host is the service name on the Docker network, shown in the Coolify service view.

  • Coolify can schedule dumps to any S3-compatible target (Hetzner Storage Box, Backblaze B2, …). The design doc's words: set this up on day one, because nothing else will. Once the email suite lands, a lost action table means lost undo history, not just vote counts.

PHASE 3

PlanetScale: the 24-hour window — export only

where: local terminal · skip this phase if the window is gone

Treat the window as export-only. Do not use it to test the new server, tune the schema, or debug anything — get a verified dump onto local disk, then close it and work at leisure.

  • pscale database dump <DATABASE> <BRANCH> --output ./pscale-dump

    Fallback, if you'd rather use mysqldump with the dashboard connection string — these flags matter, PlanetScale rejects table locks and the default GTID/tablespace statements:

    mysqldump --host=<HOST> --user=<USER> --password=<PASSWORD> \
  --ssl-mode=VERIFY_IDENTITY --ssl-ca=/etc/ssl/cert.pem \
  --single-transaction --skip-lock-tables --no-tablespaces --set-gtid-purged=OFF \
  <DATABASE> > flext-full.sql

  • The ten tables deleted from the schema on 2026-07-26 may still hold data. Discarding data later is free; a second window may not be.

  • ls -lh flext-full.sql                        # non-trivial size
grep -c "INSERT INTO" flext-full.sql         # > 0
grep -oE "CREATE TABLE \`[A-Za-z]+\`" flext-full.sql | sort -u   # expected tables present
grep -c "INSERT INTO \`Books\`" flext-full.sql                    # Books is the row that matters

    Books is the only table with data worth keeping — roughly 95 rows including the vote counts. The auth tables are empty; /auth/* never had users. A dump you have not inspected is not a backup.

PHASE 4

Restore locally and prove the chain

where: local terminal · no time pressure · skip if Phase 3 was skipped

  • docker run -d --name flext-mysql -e MYSQL_ROOT_PASSWORD=root \
  -e MYSQL_DATABASE=flext -p 3306:3306 mysql:8
mysql -h127.0.0.1 -uroot -proot flext < flext-full.sql
mysql -h127.0.0.1 -uroot -proot flext \
  -e "SELECT COUNT(*) FROM Books; SELECT name, votes FROM Books ORDER BY votes DESC LIMIT 5;"

  • Set local DATABASE_URL to mysql://root:root@localhost:3306/flext, restart the dev server, and confirm /books shows the real list with non-zero votes — not the 87-row static fallback it renders when the database is unreachable. That single check proves the whole chain end to end.

PHASE 5

Coolify: create the app service and load the data

where: coolify dashboard + local terminal

  • The settings, verbatim from the Dockerfile header:

    • Build Pack → Dockerfile
    • Dockerfile location → /Dockerfile
    • Port → 3000

    The image has its own HEALTHCHECK hitting /api/health every 30s (deliberately DB-free, so a database blip can't cause a restart loop). No build-time env is needed — the build reads no environment at all.

  • VariableValue
    DATABASE_URLmysql://user:pass@host:3306/flext — the Coolify MySQL service from Phase 2
    DATABASE_CA_PATHOptional. Only if MySQL TLS terminates outside the Docker network — leave unset for the private-network setup above.
    MAIL_ENCRYPTION_KEYThe 64-hex-char key from Phase 1 (already backed up separately).
    ADMIN_EMAILThe single account permitted to sign in.
    JWT_SECRETThe ≥ 32-char secret from Phase 1. Used by server/auth/jwt.ts.

  • With a dump (Phases 3–4 ran): restore flext-full.sql into the Coolify MySQL — easiest via a shell on the MySQL container in Coolify, or a temporary SSH tunnel to the box. Same mysql < flext-full.sql as Phase 4.

    Without a dump (window was gone): generate the schema SQL locally with bun run db:generate (drizzle-kit writes it to server/db/migrations/), apply it manually against the Coolify MySQL, then reseed Books from content/books.tsx — the seed snippet lives in the database design doc under Option D. Votes start at zero.

    • Container reports healthy (the built-in healthcheck passes)
    • /api/health returns {"ok":true}
    • /books renders from the database (non-zero votes if the dump was restored)
    • /auth sign-in works with ADMIN_EMAIL
    Note

    Signup is deliberately disabled, so sign-in needs a User row for ADMIN_EMAIL to already exist. If the restored dump doesn't contain one (the auth tables were empty on PlanetScale), creating it is a one-off manual insert — surface the SQL when you get there rather than improvising it.

PHASE 6

DNS cutover to flext.dev

where: dns provider + coolify · keep the current host running until every check is green

  • Makes the cutover (and any rollback) take minutes instead of hours.

    • A record for flext.dev → the Hetzner IPv4 from Phase 1
    • AAAA record → the IPv6, if the server has one
    • www → same target (or a redirect, if the provider offers one)
    • Remove the old host's records (the .env still carries Vercel variables, suggesting that's where the site lives today)

  • On the app service. Coolify's proxy will request the Let's Encrypt certificate automatically — this needs the DNS records above to already resolve to the box, so do it after the records are in.

  • curl -s https://flext.dev/api/health          # {"ok":true}
curl -sI https://flext.dev | head -1           # HTTP/2 200
    • Certificate is valid Let's Encrypt (padlock, no warnings)
    • /books and a couple of blog posts render correctly
    • /admin sign-in works over the real domain

  • Pause or delete the old deployment project. Not before.

PHASE 7

Aftercare — and what this unblocks

where: mixed · none of this is launch-blocking

  • Pull one scheduled dump from S3 and restore it into a local container once. An unverified backup pipeline is the same as no backup pipeline.

  • They were deleted from server/db/schema.ts on 2026-07-26 but a restored dump still contains them.

  • src/routes/books.tsx:40 derives id from isbn10, which breaks upvotes silently whenever the fallback runs. With the database live it stops running, but it stays wrong for the next outage.

  • The spec marked it decided on 2026-07-27 (self-hosted MySQL on Coolify). Two stale references in CLAUDE.md should be updated once the migration is real.

  • With a live Coolify MySQL, the 18-task connect + sync plan (docs/plans/active/2026-07-28-email-phase-1-connect-sync.md) is unblocked: its schema task needs the reachable database, and its final task adds a SCRIPT_SECRET env var plus two Coolify scheduled tasks:

    # every 15 minutes
curl -fsS -X POST -H "Authorization: Bearer $SCRIPT_SECRET" \
  "https://flext.dev/api/mail-sync?mode=incremental"
# hourly
curl -fsS -X POST -H "Authorization: Bearer $SCRIPT_SECRET" \
  "https://flext.dev/api/mail-sync?mode=reconcile"
    Open question for phase 1

    App-password / IMAP availability on the Workspace domain you don't administer must be confirmed before the sync runs against that mailbox. Nothing in the plan unblocks it; the fallback is asking that admin to allowlist an OAuth client ID.
